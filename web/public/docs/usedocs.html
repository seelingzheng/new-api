1注册并准备余额

打开 NextToken 官网注册账号。按需要购买余额或订阅；已有兑换码则先完成兑换。

2创建 API Key

在控制台生成 API Key。使用 Codex 时，Key 的分组需要选择 Codex；其他工具按对应教程要求选择。

3选择客户端

只选你实际要用的工具即可，例如 Codex、Claude Code、OpenClaw、OpenCode 或 Hermes。

4下载安装

进入“准备工作”，从统一安装表打开对应官网或下载地址，再回到该工具文章继续。

5填写 NextToken 配置

按文章中的 URL、API Key、模型名和配置文件位置填写。Base URL 常见为 https://nextoken.win/v1。

6验证是否可用

启动对应客户端，发送一条简单请求或读取项目，确认没有认证、模型或连接错误。

开始前要准备什么

  • 一个可正常登录的 NextToken 账号。
  • 余额、订阅或已经完成兑换的额度。
  • 一个与目标工具匹配的 API Key。
  • 你准备使用的客户端，例如 Codex、Claude Code、OpenClaw、OpenCode 或 Hermes。

API Key 最容易出错的地方

Codex：创建 Key 时分组需要选择 Codex。如果 Key 分组不匹配，即使 Key 本身没有复制错误，也可能无法正常调用。

复制 API Key 时不要多复制空格，也不要把示例里的 sk-你的API Key 当成真实值。配置完成后，如果出现 401 / 403，优先回到控制台确认 Key、分组和权限。

客户端怎么选

需求建议进入的教程
桌面端使用 Codex 或终端编程3. Codex
使用 Claude Code CLI、桌面 Code 或 VS Code 插件4. Claude Code
把模型接入 Gateway / 多渠道 Agent5. OpenClaw
使用开放的终端 / 桌面 Coding Agent6. OpenCode
使用 Nous Research Hermes7. Hermes Agent
想用图形界面给多个工具配置 NextToken2. CC Switch

配置完成后怎么判断成功

  1. 客户端可以正常启动。
  2. 发送请求后没有出现 401 / 403 等认证错误。
  3. 没有出现“模型不存在”或 provider / protocol 配置错误。
  4. 可以正常得到模型回复；Coding Agent 可以读取当前项目或执行最基本任务。
建议：第一次只做最小验证。确认链路可用后，再继续配置模型切换、插件、Gateway 或其他高级能力。

2. 用 CC Switch 配置 NextToken

CC Switch + NextToken：先记住这几个地址

这一章只解决一个问题：安装 CC Switch，然后用它把 NextToken 配置到 Claude Code、Codex、OpenCode、OpenClaw、Hermes 等客户端中。如果你不想手工修改 JSON、TOML 或环境变量，优先用 CC Switch 会更直观。

2.1 下载与安装 CC Switch

2.2 打开 CC Switch，先选择要配置的工具

启动后，顶部可以切换 Claude、Codex、Gemini、OpenCode、OpenClaw、Hermes 等应用。这里不是选择模型，而是选择“你准备让 NextToken 给哪个客户端提供 API”。

推荐顺序：先选客户端 → 点击右上角 + → 新建 NextToken 配置 → 填 API Key / URL / 模型 → 保存 → 启用。

2.3 新建 NextToken 配置

NextToken：https://nextoken.win　·　API：https://nextoken.win/v1

在目标客户端页签中点击右上角 +，打开“添加供应商”。如果没有 NextToken 预设，就选择 Custom / 自定义。

通用字段可以按下面填写：

字段建议填写
名称NextToken
API Key粘贴你在 https://nextoken.win 创建的 Key
Base URL按客户端选择 https://nextoken.win 或 https://nextoken.win/v1
模型填写你在 NextToken 当前可用的模型 ID
协议按目标客户端选择 Anthropic / OpenAI Responses 等对应协议
不要把所有客户端都填成完全相同的 URL / 协议。 Claude Code 和 Codex 的配置方式不同，下面分别给出。

2.4 用 CC Switch 配置 Claude Code

URL：https://nextoken.win　·　配置文件：~/.claude/settings.json

顶部切换到 Claude，然后添加一个自定义供应商：

字段值
名称NextToken
Base URLhttps://nextoken.win
API Key你的 NextToken API Key
协议Anthropic / Claude Code 对应协议
模型选择或填写 NextToken 可用 Claude 模型

保存后点击 启用。CC Switch 会把相应配置写入 Claude Code 使用的配置文件，通常不需要你再手工编辑。

如果 Claude Code 已经打开，建议先退出 Claude Code，再在 CC Switch 中启用 NextToken，然后重新启动 Claude Code。

2.5 用 CC Switch 配置 Codex

URL：https://nextoken.win/v1　·　Key 分组：Codex

顶部切换到 Codex，新建 NextToken 自定义供应商。Codex 使用 NextToken 时，API Key 必须创建在 Codex 分组。

字段值
名称NextToken
Base URLhttps://nextoken.win/v1
API KeyNextToken 的 Codex 分组 Key
模型例如 gpt-5.5，以当前可用模型为准
协议Codex / Responses 对应协议

部分版本的 CC Switch 会显示“本地路由 / 接管”选项。如果你的配置模板要求开启，就按模板启用；如果普通自定义配置已经能正常调用，不需要额外打开。

2.6 OpenCode、OpenClaw、Hermes 怎么配置

这几个客户端在 CC Switch 里的操作逻辑相同：先切换到对应页签，再新增 NextToken 自定义供应商。

客户端NextToken URL配置重点
OpenCodehttps://nextoken.win/v1填写 API Key、模型，并选择与模型匹配的协议
OpenClawhttps://nextoken.win/v1Provider 指向 NextToken，模型 ID 与控制台保持一致
Hermeshttps://nextoken.win/v1使用 Custom endpoint / 自定义端点思路配置

如果某个客户端页签里没有现成的 NextToken 模板，直接用 Custom / 自定义 即可，不需要去选择其他第三方供应商的预设。

2.7 保存、启用并验证

填写完成后点击保存，然后在 NextToken 供应商卡片上点击 启用。

建议按下面顺序验证：

  1. 退出当前正在运行的 Claude Code / Codex / OpenCode 等客户端。
  2. 在 CC Switch 中确认 NextToken 已启用。
  3. 重新打开对应客户端。
  4. 发一条最简单的消息，例如“你好，你是什么模型？”。
  5. 如果能正常返回内容，说明 NextToken 配置已经生效。

2.8 常见问题

2.8.1 401 / 403

优先检查 API Key 是否完整，以及 Key 是否属于正确分组。特别是 Codex，请确认创建的是 Codex 分组 Key。

2.8.2 模型不存在

检查 CC Switch 中填写的模型 ID 是否与 NextToken 当前实际可用模型一致，不要照抄其他供应商的模型名称。

2.8.3 点击启用后仍然走旧配置

关闭对应客户端后重新启用 NextToken，再重新打开。若仍不生效，检查是否同时存在环境变量、手工配置文件和 CC Switch 三套配置互相覆盖。

2.8.4 Base URL 应该填哪个？

  • Claude Code：优先使用 https://nextoken.win
  • Codex / OpenCode / OpenClaw / Hermes：通常使用 https://nextoken.win/v1

2.8.5 Linux AppImage 无法点击或黑屏

CC_SWITCH_GDK_BACKEND=wayland ./CC-Switch-*.AppImage
# 或
CC_SWITCH_GDK_BACKEND=x11 ./CC-Switch-*.AppImage

4.2 配置 Claude Code 使用中转服务

配置文件：~/.claude/settings.json　·　URL：https://nextoken.win

这是最关键的一步——让 Claude Code 连接到我们的中转服务，而不是 Anthropic 官方 API。

4.2.1 方法一：环境变量配置（推荐）

4.2.1.1 macOS / Linux / WSL2

编辑你的 shell 配置文件：

# 如果你用的是 zsh（macOS 默认）
nano ~/.zshrc

# 如果你用的是 bash
nano ~/.bashrc

在文件末尾添加：

export ANTHROPIC_BASE_URL="https://nextoken.win"
export ANTHROPIC_AUTH_TOKEN="sk-你的API Key"

保存退出后执行：

source ~/.zshrc  # 或 source ~/.bashrc
4.2.1.2 Windows PowerShell
$env:ANTHROPIC_BASE_URL = "https://nextoken.win"
$env:ANTHROPIC_AUTH_TOKEN = "sk-你的API Key"

设置后重新打开 PowerShell 生效。

4.2.1.3 Windows（通过 setx 命令）
setx ANTHROPIC_BASE_URL "https://nextoken.win"
setx ANTHROPIC_AUTH_TOKEN "你的 key"

4.2.2 方法二：Claude Code 设置文件

在终端中运行 claude 进入交互模式，输入 /config 打开设置，或者直接编辑 ~/.claude/settings.json：

{
  "env": {
    "ANTHROPIC_BASE_URL": "https://nextoken.win",
    "ANTHROPIC_AUTH_TOKEN": "sk-你的API Key"
  }
}

验证配置：

cd 任意一个项目目录
claude
/model opus

4.4.2 配置环境变量

    "ANTHROPIC_BASE_URL": "https://nextoken.win",
    "ANTHROPIC_API_KEY": "sk-你的API Key"
  },
  "claudeCode.environmentVariables": [
    { "name": "ANTHROPIC_BASE_URL", "value": "https://nextoken.win" },

  ]
}

如果仍提示登录：先确认 VS Code 已完全退出并重新打开，再检查 settings.json 中的 URL 与 API Key 是否写入正确；如果终端已经配置环境变量，也要确认 VS Code 是从同一用户环境启动。

12 常见问题

遇到问题时，先判断属于“安装启动、API 认证、模型协议、配置不生效还是桌面端”。大多数问题都可以在对应配置文件、URL 和 API Key 这三处定位。

12.1 安装与启动

安装完成后提示 command not found？

先确认工具是否真的安装成功，再关闭并重新打开终端。常用验证命令包括：

node -v
claude --version
codex --version
opencode --help

如果安装成功但命令仍找不到，通常需要检查安装目录是否已经加入系统 PATH。

Windows 上 CLI 使用不顺怎么办？

优先使用对应的 Windows 桌面端；需要 Linux 风格环境时，可以安装 WSL2：

wsl --install

安装地址应该去哪里找？

统一进入“1. 准备工作 → 1.1 软件安装地址”。本文后面的教程只使用文章开头已经列出的 URL，不再要求另外查找下载地址。

12.2 API Key、401 / 403 与认证

报错 401 Unauthorized？

  • 检查 API Key 是否复制完整，前后不要带空格。
  • 确认配置文件里没有仍然保留示例值，例如 sk-你的API Key。
  • 确认 Base URL 与当前教程一致。

Codex 的 Key 明明正确，为什么仍然不能用？

Codex 创建 API Key 时，分组需要选择 Codex。Key 本身正确但分组不匹配，也可能导致调用失败。

应该填哪个 Base URL？

OpenAI Compatible / Codex / OpenCode 等配置中常见为：

https://nextoken.win/v1

Claude Code 等 Anthropic 配置请以对应文章顶部的 URL 和配置示例为准，不要在不同工具之间直接照搬。

12.3 模型、Provider 与协议

提示 model not found / 模型不存在？

  • 确认模型 ID 与控制台当前可用模型一致。
  • 确认当前 API Key 有对应模型权限。
  • 检查配置文件中有没有旧模型名或拼写错误。

OpenCode 能启动，但调用模型时报错？

当前文档中的 OpenCode 配置要求使用 anthropic 协议。如果把 Claude 模型误配成 openai 协议，可能导致调用失败。

Codex 配置文件主要看哪里？

优先检查：

~/.codex/auth.json
~/.codex/config.toml

Windows 对应目录一般位于 %USERPROFILE%\.codex\。

12.4 配置修改后没有生效

改完配置还是使用旧配置？

  • CLI：关闭当前终端后重新打开。
  • CC Switch：确认目标供应商已经点击“启用”。
  • OpenClaw：修改后执行 openclaw gateway restart。
  • Claude Code / Codex：检查是否同时存在多个配置来源，导致旧值覆盖新值。

OpenClaw 修改模型后仍然异常？

除主配置外，还可以检查是否存在旧模型缓存：

~/.openclaw/agents/main/agent/models.json

修改后重新启动 Gateway，再执行 openclaw status 和 openclaw doctor。

CC Switch 点击“启用”后没变化？

先退出正在运行的 Claude Code、Codex、Gemini CLI 等工具，重新启用供应商，再重新打开对应客户端。

12.5 桌面端与插件

Codex 桌面端安装后在哪里？

新版桌面端安装完成后，打开 ChatGPT Desktop，在左上角切换到 Codex 工作区即可。Codex 桌面端和 Codex CLI 是两种入口，不要求同时安装。

Claude Code VS Code 插件安装后找不到？

按 Cmd+Shift+P（macOS）或 Ctrl+Shift+P（Windows / Linux），输入 Claude Code，再选择对应命令打开。

OpenCode / Hermes / OpenClaw 桌面版与 CLI 怎么选？

只想图形化使用时优先桌面版；需要终端自动化、配置文件控制或开发环境集成时再使用 CLI。两者不需要为了“完整安装”而全部安装。

12.6 请求超时与生成任务

图像生成为什么一直等到超时？

gpt-image-2 的同步生图请求耗时可能较长，本文建议客户端超时设置到 600 秒。如果不希望长期保持连接，可以改用异步生图流程。

视频生成为什么不能立即返回视频？

Seedance 和 Grok 视频都是任务型流程，通常需要先创建任务，再轮询状态，最后获取生成结果。不要把它当作普通即时文本接口处理。
